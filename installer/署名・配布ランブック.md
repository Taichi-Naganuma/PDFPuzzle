## 1. 事前準備 (証明書到着後・一度だけ)

### 1-1. SSL.com EV 証明書が有効か確認 ★人間の判断が必要
SSL.com アカウントにログインし、Sole Proprietor EV Code Signing 証明書が
**Issued / Active** になっていること、eSigner が有効化されていることを確認する。
未発行・審査中ならここで停止。先に進めない。

### 1-2. CodeSignTool を導入
このマシンには **Java が入っていない**ため、必ず **JRE 同梱版**を使う。

1. https://www.ssl.com/download/codesigntool-for-windows/ から
   **「CodeSignTool ... (with JRE)」** の ZIP を取得。
2. `C:\Program Files\SSL.com\CodeSignTool\` に解凍する
   (= `CodeSignTool.bat` がこのパス直下に来るように)。
   - 別の場所に置く場合は §2 の `sign-installer.ps1` に
     `-CodeSignToolPath "<解凍先>\CodeSignTool.bat"` を付ける。
3. 確認:
   ```powershell
   Test-Path "C:\Program Files\SSL.com\CodeSignTool\CodeSignTool.bat"   # → True
   ```

### 1-3. 認証情報を環境変数に投入 ★機密・オーナーが入力
**この4つは絶対にファイル/コミットに残さない。** その場の PowerShell セッションに直接打つ。
```powershell
$env:ESIGNER_USERNAME      = "<SSL.com ログイン用メール>"
$env:ESIGNER_PASSWORD      = "<SSL.com パスワード>"
$env:ESIGNER_TOTP_SECRET   = "<eSigner TOTP シークレット (Base32)>"
$env:ESIGNER_CREDENTIAL_ID = "<eSigner credential id>"
```
> TOTP シークレットは eSigner の「自動署名用」設定画面で取得する6桁コードの
> *元シークレット* (QR の下に出る文字列)。ワンタイム6桁の値ではない。

## 2. 一発実行シーケンス (署名 → 再パッケージ → 検証)

`installer\` をカレントにして、上から順に実行する。**途中で exit≠0 が出たら止めて §4 を見る。**

```powershell
cd "C:\Users\zhang\source\repos\desk-fire\PDFPuzzle\installer"

# (a) EV 署名 — output\ の未署名 EXE をその場で署名上書き
.\sign-installer.ps1 -InstallerPath ".\output\PDFPuzzle_Setup_v1.0.0.exe"
if ($LASTEXITCODE -ne 0) { Write-Host "SIGN FAILED ($LASTEXITCODE) — STOP"; return }

# (b) 署名済み EXE で配布 ZIP を作り直す  ★ここを飛ばすと未署名 ZIP が出荷される
.\package-release.ps1
if ($LASTEXITCODE -ne 0) { Write-Host "PACKAGE FAILED ($LASTEXITCODE) — STOP"; return }

# (c) 配布ゲート — EXE と ZIP 内 EXE の両方が Valid 署名か + バージョン一致を機械検証
.\verify-signed-package.ps1
if ($LASTEXITCODE -ne 0) { Write-Host "VERIFY FAILED ($LASTEXITCODE) — DO NOT SHIP"; return }

Write-Host "OK — output\PDFPuzzle_v1.0.0.zip は配布可能"
```

完走すると `output\PDFPuzzle_v1.0.0.zip` が **署名済み EXE + README** 同梱の最終形になる。
これが Gumroad / STORES にアップロードする現物 (配布操作はオーナー §5③)。

> **なぜ (b) が必須か**: `package-release.ps1` は EXE を ZIP に*コピー*する。
> 署名は EXE ファイル自体に埋まるので、署名する前に作った ZIP には未署名 EXE が
> 入ったまま。`verify-signed-package.ps1` はこの取り違えを (c) で検出する
> (ZIP から EXE を取り出して署名状態を再チェックする)。

## 3. 目視確認 (機械チェックの裏取り・任意だが推奨)

```powershell
# エクスプローラで EXE を右クリック → プロパティ → [デジタル署名] タブに
# "desk-fire" の署名 + タイムスタンプが出ることを確認
Get-AuthenticodeSignature ".\output\PDFPuzzle_Setup_v1.0.0.exe" | Format-List Status, SignerCertificate, TimeStamperCertificate
```
- `Status` = `Valid`
- 署名者 Subject に `desk-fire` (= はじめにお読みください.txt の記載と一致)
- `TimeStamperCertificate` が非 null (タイムスタンプ付与済 = 証明書失効後も検証可)

## 4. 失敗時の切り分け (`sign-installer.ps1` の exit コード)

| exit | 意味 | 対処 |
|---|---|---|
| 1 | `ESIGNER_*` 未設定 | §1-3 を実行してから再実行 |
| 2 | InstallerPath 不正 | EXE パス/存在を確認 |
| 3 | CodeSignTool.bat が無い | §1-2 を実行、または `-CodeSignToolPath` 指定 |
| 4 | signtool.exe が無い | Windows SDK 導入、または `-SigntoolPath` 指定 (検証段のみ) |
| 5 | 署名検証に失敗 | 証明書/credential 設定を確認。CodeSignTool ログ参照 |
| 7 | CodeSignTool 非ゼロ終了 | TOTP ずれ (時刻同期) / credential_id 誤り / 残署名回数切れ を疑う |

> `signtool.exe` が無い (exit 4) 場合でも署名自体は (b) 完了後に成立している。
> その時は §3 の `Get-AuthenticodeSignature` と `verify-signed-package.ps1` (signtool 不要) で
> 検証すればよい。`sign-installer.ps1` 末尾の signtool 検証だけが落ちている状態。
